## Docker development

From the repository root, copy `.env.example` to `.env` and run `docker compose up --build`. Start Docker Desktop first if using it. Open `http://localhost:5180`; `http://localhost:3001/health` checks API process availability and `/ready` checks database readiness.

The local stack includes the frontend, API, AI service, MongoDB, Redis, and MinIO. MongoDB uses host port 27018, Redis 6379, and MinIO 19000/19001. App services use 5180, 3001, and 8000. Keep the example credentials limited to local development. See [production operations](production-operations.md) before preparing a shared deployment.

Create an account using the local registration form, create a workspace, then open **Company data**. Prepare the labeled sample, review it, and import it. This is the quickest way to inspect connected evidence without provider credentials.

## Expanded synthetic walkthrough

The larger demo is generated by source-controlled scripts rather than a copy of a personal database. With the Docker stack running and a registered account, list local user IDs:

```sh
docker compose exec mongo mongosh genesis --quiet --eval 'db.users.find({}, {_id: 1, name: 1}).forEach(printjson)'
```

Run the seed script with the ID of the account that should own the demo:

```sh
docker compose exec api node scripts/seed-demo.mjs YOUR_USER_ID
```

The script prints the new workspace ID. Use that ID to enrich the demo:

```sh
docker compose exec api node scripts/enrich-demo.mjs YOUR_DEMO_WORKSPACE_ID
```

Refresh the UI and select **Genesis Demo — Synthetic**. Seeding creates a new demo workspace on each invocation. Enrichment applies only to the synthetic workspace and checks whether its final observation is already loaded. These scripts write fictional records; they do not configure or publish to external providers. Follow the [founder walkthrough](founder-preview.md) to explore the result.

## Developing services locally

Use Node.js 22.12+ and Python 3.11. Install dependencies with the commands in the root README. Start MongoDB and Redis with `docker compose up -d mongo redis`, then use separate terminals:

```sh
# From api/
MONGO_URI=mongodb://127.0.0.1:27018/genesis REDIS_URL=redis://127.0.0.1:6379 API_PORT=3001 npm start

# From web/
npm run dev
```

This is enough for the company-intelligence UI. Startup analysis also needs the AI service and artifact storage. The full Compose stack is the simplest way to run those dependencies together. The root `.env` is consumed by Compose; shell-launched services need environment variables supplied explicitly.

## Providers and authentication

- Set `GROQ_API_KEY` for Groq, or choose and configure Ollama with `LLM_PROVIDER` and `OLLAMA_BASE_URL`.
- Keep matching `INTERNAL_API_TOKEN` values in the API and AI service for callbacks.
- Google OAuth backend configuration is present, but the current local-preview UI uses email/password registration. A complete Google sign-in flow still needs configuration and verification.
- GitHub and ingestion connections are optional and workspace-scoped. Review their permissions and configuration in the [feature status](remaining-features-status.md) and [operations guide](production-operations.md).

## Integration scripts

`api/scripts/integration.mjs` and `api/scripts/review-extended.mjs` exercise a running API at port 3002. The former uses `TEST_API_URL` when supplied and connects to `TEST_MONGO_URI` (default `mongodb://127.0.0.1:27017/genesis-integration`). Check those values against the API's `MONGO_URI` before running. Use an isolated test database, not an existing company database. These scripts create test accounts and workspaces and retain them for inspection.
